Ordivon Host

Replace the cognition or process without replacing the admitted semantic work claim—and without copying foreign owner truth into Host.

The durable semantic work-continuity component for Ordivon. Host preserves what work is being continued and what was last claimed, while cognition, physical execution, source currentness, external occurrence, and domain acceptance stay with their own owners.

Projected status
Operational owner-trusted local engineering component; pre-1.0 public interface
For
Builders and Agent workflows that need semantic work to survive conversation/session replacement without adopting a workflow platform, central coordinator, Runtime proxy, or generic cognition host.
Evidence for status
The 0.3 contraction removed unconsumed Goal coordination, foreign execution, legacy execution workloads, generic capability policy, and Runtime-integration residue. Current 0.4.x then makes external semantic continuity first-class: one WorkingCheckpoint can survive client replacement with revision-coherent resume and exact response-loss replay, while every Runtime/Git/domain hint remains explicitly subject to owner-native revalidation.

Question this project must answer

Which bounded semantic work claims must survive session replacement, and which Runtime, Git, Provider, or domain facts must instead be revalidated with their native owners?
